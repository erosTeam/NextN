# NextN 当前总 Goal 与工作约束

## 活跃 Goal 提示词

持续把 NextN 交付为一个可长期使用、功能正确且视觉一致的 HarmonyOS 应用。以
NextE / ErosN 的完整页面父树、交互所有权、状态流和真实设备结果作为实现依据；保留
NextN 的数据源、账户模型和已存在产品能力。当前已发现的问题必须由代理自行审查、
定位并修复，不把逐页 QA 责任交给用户；用户指出的问题只校正对应边界，不能借机
扩展成未授权的重写或行为替代。

账户持久化具有抢占优先级：只要当前原生 Account 或 Favorites 证明登录失效，立即
冻结其它开发，进入唯一 P0。先记录无敏感 S0、计时及恢复/401 阶段，追踪账户唯一
所有者和全部写入、删除、失效、迁移、请求与进程死亡顺序，修复被当前证据证明的
错误转移。重新登录只可用于修复后 record-present 验证，绝不掩盖原因；使用固化的
语义 WebView 流程连续完成一次输入/一次提交。P0 仅在真实登录经 force-stop/cold
start 后原生 Account 保持认证、Favorites 完成 authenticated read，并写出根因及此前
失败复盘后才解除。

所有 UI 和设备操作必须区分“建链”和“执行”。首次可用截图、参考和当前状态建立
语义入口、直接 intent 或明确分支；已确认的普通操作链随后一次连续执行到底，不在
每一步重新读取源码、截图、解析布局、推理或猜坐标。截图/多模态只用于首次建链、
会改变下一步的真实分支、最终验收或异常诊断。重复页面优先增加通用 direct intent
或既有语义入口，例如 `galleryId + destination=comments`，而不是用滚动和旧截图坐标
重建路线。终态不符只保留一张诊断证据、修复整条链后再跑；用户要求审计时，将截图
保存在命名的本地审计目录且不自动删除、不提交原图。

可见改动先映射同一页面完整父树：scroll owner、chrome、section、顺序、几何、状态
转移和动作所有者。复用 NextE / ErosN 已有 scaffold、组件和状态模式；NextN 差异只
替换有证据的数据叶或不支持叶。横向 List 的中段 viewport 必须覆盖副容器内部完整
宽度，首尾留白只能由 List 自身的 leading/trailing 内容承担，标题与非滚动节点不越出
父容器。禁止创建、运行、更新或引用 UI 静态合同、source-shape 检查、合成 fixture、
布局 matcher 或自造摘要工具作为视觉/交互验收。构建、安装、源码相似和单帧不等于
验收；可见结论必须来自同状态、同视口的真实设备与参考比较。

每项功能或布局修改完成后，立即检查精确 diff、`git diff --check` 并单独提交该项；不
积累多个未提交 UI/功能修改，也不把未完成的不同问题混进一个提交。构建和真实设备
复核随后进行；发现新的独立问题，以新的窄改动和新的提交处理。任务不会因为问题、
质疑、构建、局部截图或一个子任务结束而停止；只有用户明确停止，或已声明结果都
取得所需真实证据时才允许结束。

## 当前执行顺序

1. **P0（条件触发）账户持久化**：按上文抢占规则执行；每次失效/登录周期写入
   `docs/qa/nextn-login-attempt-ledger.md`，记录时间、阶段、耗时和累计耗时，不记录
   凭据、cookie、URL、个人资料、原始布局或截图。
2. **P1 Gallery Detail / Comments**：用当前通用直达路由和保留的真实审计图，继续
   修复被实际画面证明的 Preview、Related、横向评论预览、完整评论页以及 Read rail 的
   父树、尺寸、滚动边界和加载状态；每个问题独立改、独立提交、同状态实机复核。
3. **P2 页面族与未完成能力**：在当前页面完整复核后，再按真实主路径影响审查根列表、
   Search、Favorites、History、Downloads、Reader、Settings 等页面族的功能与生命周期；
   不删除 NH 能力、不用参考缺失替代现有产品行为。

## 不能替代本 Goal 的文件

`AGENTS.md`、`docs/controls/nextn-execution-integrity.md` 和登录设备协议中的更严格
规则优先；它们与本 Goal 一起约束每个恢复的回合。
